# Архитектура Dharma Sitemap

Статус документа: архитектура MVP `0.1.0` и дальнейший план, 2026-10-16.

## Состояние первой реализации

В пакете `0.1.0` уже есть компонент с ручным запуском, планировщик Joomla Scheduler, поставщики материалов и категорий Joomla, контактов, лент новостей, меток и адаптер Dharma Shop для товаров и категорий. Сборка запускает поставщиков по очереди, удаляет повторы по нормализованному URL и ключу сущности, пишет файлы в отдельный каталог и меняет активную сборку только после успешного завершения.

В MVP одна сборка выполняется целиком за один HTTP-запрос или один запуск Scheduler. Возобновляемые порции между запусками, периодическая очистка старых записей/файлов, проверка `noindex`, сбор URL из пунктов меню, gzip и короткий маршрут `/sitemap.xml` пока не реализованы. Источники пропускаются при недоступности; при исключении источника текущая сборка завершается ошибкой и предыдущая карта остаётся активной. Перед выпуском следует проверить пределы времени и памяти на реальном размере каталога.

## 1. Назначение и границы

Dharma Sitemap — Joomla-компонент, который объединяет адреса страниц от нескольких поставщиков, проверяет их пригодность для индексации, устраняет совпадения и публикует стандартную XML-карту сайта. Компонент не меняет материалы и настройки SEO других расширений, не генерирует страницы каталога и не отправляет карту поисковикам.

Первая поставка — отдельный пакет `pkg_dharmasitemap`, со своим репозиторием, нумерацией версий, сборкой и update feed. Dharma Shop остаётся независимым расширением; интеграция подключается через адаптер-плагин и должна корректно отключаться, если Dharma Shop не установлен.

## 2. Состав системы

### `com_dharmasitemap`

- Административный интерфейс Joomla: обзор последней сборки, кнопка запуска/продолжения, ошибки источников, параметры карты.
- Публичный XML-контроллер для sitemap index и частей карты.
- Координатор сборки, нормализатор URL, дедупликатор, XML writer, хранение текущей публикации и журнал запусков.
- Плагин задачи Joomla Scheduler для автоматической пересборки; ручной запуск остаётся доступным.
- Защитные ограничения и ACL на изменение конфигурации и запуск операций.

### Плагины-поставщики

Поставщики изолируют знания о структуре расширения от ядра компонента. Каждая реализация возвращает описание источника и ограниченные порции кандидатов, а не строит XML самостоятельно.

Предлагаемые плагины первой линии:

- `plg_dharmasitemap_content` — материалы и категории `com_content`.
- `plg_dharmasitemap_contact` — опубликованные публичные контакты и категории `com_contact`.
- `plg_dharmasitemap_newsfeeds` — опубликованные ленты и категории `com_newsfeeds`, если расширение включено.
- `plg_dharmasitemap_tags` — публичные страницы меток `com_tags` при наличии опубликованных объектов и маршрута.
- `plg_dharmasitemap_dharmashop` — опубликованные товары и категории Dharma Shop; бренды добавляются только если для них есть поддерживаемая публичная страница/маршрут.

Поставщики проверяют существование таблиц и компонентов, но никогда не создают URL из неподтверждённых записей. Для расширения, отключённого в Joomla, источник помечается недоступным, а остальные источники продолжают работу.

## 3. Контракт расширения

Для первой версии предлагается отдельная группа Joomla-плагинов `dharmasitemap`. Компонент явно загружает эту группу перед вызовом собственного события сбора источников. Контракт находится в namespace библиотеки компонента и версионируется независимо от внутренних классов.

Условный интерфейс:

```php
interface SitemapSourceInterface
{
    public function getDefinition(): SourceDefinition;

    /** @return iterable<UrlCandidate> Порция не больше переданного лимита */
    public function fetchBatch(SourceContext $context, ?string $cursor, int $limit): SourceBatch;
}
```

`SourceDefinition` задаёт стабильный ID, приоритет, доступность, лимит, поддержку продолжения по cursor и параметры включения. `UrlCandidate` содержит URL, идентификатор сущности, язык, lastmod при наличии и объяснение маршрута. Интерфейс запрещает произвольную запись файлов, SQL-изменения и управление активной публикацией со стороны плагина.

Обработка ошибок изолирована на уровне источника: исключение фиксируется в журнале сборки, источник помечается ошибочным. Политика публикации при ошибке источника (публиковать частичный результат или сохранить старую карту целиком) — открытый вопрос перед MVP.

## 4. Потоки данных

```text
планировщик / администратор
          │
          ▼
координатор сборки ── загружает плагины-поставщики
          │
          ├── порции URL от поставщиков
          ▼
проверка маршрута и индексации
          ▼
нормализация → дедупликация → временный набор сборки
          ▼
XML sitemap parts + sitemap index во временном каталоге
          ▼
атомарное переключение active_build_id
          │
          ▼
публичный контроллер отдаёт только активную успешную сборку
```

Администратор и Scheduler используют один и тот же координатор. Одновременные сборки блокируются через lock в БД с владельцем, временем создания и безопасным снятием просроченного lock. Пакетная задача сохраняет cursor каждого поставщика, поэтому может продолжиться после тайм-аута или прерывания.

## 5. Генерация и публикация

- Сборка создаётся как новая версия, не меняя активную.
- Уникальный индекс на `(build_id, url_hash)` защищает от повторной вставки и при параллельных повторах.
- URL обрабатываются небольшими порциями с общим лимитом времени/записей на запуск.
- XML сначала записывается в staging-каталог под `JPATH_CACHE/com_dharmasitemap/`; файлы закрываются, проверяются, затем сборка атомарно становится активной сменой указателя в БД.
- До переключения посетители получают предыдущую успешную карту. Ошибка не должна заменять её пустым или повреждённым XML.
- Временные файлы и старые сборки удаляются по сроку хранения. Очистка ограничена каталогом компонента и никогда не удаляет пользовательские файлы.
- При недоступности файловой записи или базы сборка завершается диагностируемой ошибкой; активный набор остаётся доступен.

Размещение в Joomla cache не является частью ZIP и может очищаться Joomla. Компонент должен распознавать потерю файлов активной публикации и безопасно пересоздавать карту. Долговременная история содержимого XML не хранится.

## 6. Обнаружение и защита от дублей

Дедупликация выполняется в несколько уровней:

1. **Проверка кандидата:** разрешён только абсолютный HTTP(S) URL этого сайта; исключаются фрагменты, внешние домены, URL административной части, неизвестные/ошибочные маршруты и страницы без публичного доступа.
2. **Идентичность сущности:** ключ `(source_id, entity_type, entity_id, language)` предотвращает многократную выдачу одной сущности через несколько меню и плагины.
3. **Нормализация адреса:** схема/host приводятся к выбранному варианту сайта, удаляется fragment, нормализуются повторы завершающего `/` и порядок параметров. Tracking-параметры удаляются по безопасному списку. Значимые параметры Joomla (`id`, `Itemid`, `lang` и другие параметры маршрута) не удаляются без подтверждения маршрутизатора.
4. **Отпечаток URL:** SHA-256 нормализованного URL с уникальным индексом на сборку. Повтор URL объединяется, а не вставляется второй раз.
5. **Выбор канонического маршрута:** при совпадении одной сущности или URL приоритет имеют явное правило/исключение администратора, затем предпочтительный пункт меню, затем наиболее чистый SEF URL, затем приоритет источника. Выбор фиксируется в диагностике.

Настройки дублей должны объяснять причину исключения. Администратор сможет выгрузить отчёт о количестве полученных, включённых, исключённых и объединённых URL, не просматривая весь набор вручную.

Обязательные фильтры кандидатов: публикация, даты начала/окончания публикации, доступ для Public, язык, запрет индексации, исключённая категория/сущность и явный `noindex`, если они доступны штатными данными Joomla или расширения. Проверка `robots.txt` не применяется как единственный способ определить индексируемость страницы.

## 7. Стандартные и Dharma Shop источники

### Стандарт Joomla

Базовое предложение для индексируемых данных ядра: `com_content` (материалы и категории), `com_contact` (контакты и категории), `com_newsfeeds` (ленты и категории, если включены), `com_tags` (публичные метки с содержимым). Другие штатные компоненты добавляются отдельными поставщиками только если они создают публичные страницы, которые действительно следует индексировать. Источник должен брать URL через штатный маршрутизатор Joomla и учитывать пункты меню, язык, ACL и публикацию.

Главную страницу, произвольные пункты меню и страницы расширений без поддержанного поставщика не следует безусловно добавлять как отдельные дубли. Нужен список поддерживаемых типов меню и стратегия, как использовать меню для выбора чистого маршрута. `com_users`, поиск, формы авторизации, корзина/checkout и административные страницы по умолчанию исключаются.

### Dharma Shop

Отдельный адаптер поставляет публичные страницы товаров и категорий после проверки актуальной схемы `com_dharmashop`, статусов публикации/доступности и штатного построителя маршрутов. Интеграцию следует делать через публичный сервис/контракт Dharma Shop, если таковой доступен; прямые запросы к внутренним таблицам допустимы только как версионированный адаптер с проверками схемы.

Покупательские и служебные представления (корзина, заказ, избранное, личный кабинет, сравнение, фильтры с временными параметрами) не включаются. Варианты одного товара не становятся самостоятельными URL без отдельного SEO-решения.

## 8. Формат XML и адреса

- Sitemap index ссылается на XML-файлы URL; каждый файл соблюдает лимиты протокола Sitemap: не более 50 000 URL и 50 MB несжатого XML.
- Порог по умолчанию для разбиения предлагается ниже протокольного максимума; сжатие gzip — отдельное решение MVP.
- XML кодируется UTF-8 с корректным escaping URL. `lastmod` выводится только при достоверной дате изменения; `changefreq` и `priority` не создаются искусственно.
- Канонический адрес базы сайта берётся из конфигурации Joomla с возможностью явного выбора домена/HTTPS для multi-domain окружения.
- Надёжная точка входа по умолчанию: штатный URL компонента с `format=xml`; короткий `/sitemap.xml` требует документированного rewrite-маршрута для Apache/Nginx и не должен редактировать конфигурацию сервера установщиком.

## 9. Настройки и наблюдаемость

Предлагаемые группы настроек в нативной Joomla-форме:

- Публикация: канонический домен/протокол, endpoint, имя карты, режим генерации.
- Источники: доступные поставщики, включение источника, лимиты, поддерживаемые типы страниц.
- Фильтрация: языки, категории/сущности, ACL, даты публикации, правила исключения и `noindex`.
- Дубли: tracking-параметры, значимые query-параметры, приоритет маршрута и поведение при конфликте.
- Автоматизация: расписание, порция работы, timeout/лимиты, хранение журнала.
- Диагностика: последняя сборка, длительность, счётчики, ошибки по источникам, тестовый URL preview.

Опции проектируются для обычного администратора: безопасные значения по умолчанию, пояснения к потенциально широким параметрам и контроль итогового числа URL. В интерфейс не выводятся секреты; публичная выдача доступна только для чтения.

## 10. Безопасность и эксплуатационные ограничения

- На сайте не запускается полное сканирование каталога при каждом HTTP-запросе к карте.
- Публичный endpoint не принимает произвольные SQL-фильтры, пути файлов, имена источников или произвольные URL.
- Все настройки и ручные действия защищены Joomla ACL, CSRF токеном и проверкой прав; вывод экранируется штатными средствами Joomla.
- Поставщик ограничен размером порции, временем и лимитом кандидатов; источник не может добавить внешний URL или обойти общие фильтры.
- Только компонент управляет временными каталогами и активным указателем. File/path операции должны гарантировать нахождение внутри выделенного каталога.
- XML соответствует ожидаемому формату, ошибки источников доступны в административной диагностике без показа stack trace анонимному посетителю.
- Ошибка или остановка Scheduler не выводит частичную карту и не сбрасывает предыдущую рабочую версию.

## 11. Установка, пакет и обновления

Один самостоятельный пакет `pkg_dharmasitemap` включает компонент, штатные source-плагины Joomla, адаптер Dharma Shop и task plugin. Установка Dharma Shop необязательна. Каждое расширение имеет согласованный пакетный номер версии.

Публичный `updates.xml` публикуется в этом репозитории и содержит тип/element/version/client/совместимость, install ZIP URL и SHA-256. GitHub Actions:

1. Проверяет манифесты, XML, версии пакета и вложенных расширений.
2. Собирает installable ZIP из allowlist-файлов и проверяет архив.
3. Считает SHA-256, создаёт тег и GitHub Release с ZIP.
4. Обновляет `updates.xml` в основной ветке ссылкой на выпущенный ZIP.
5. Проверяет XML и совпадение checksum до публикации результата.

Лента нужна в манифесте пакета `<updateservers>`. Обновление проверяется из Joomla через список расширений/сайтов обновлений. Смена схемы БД требует идемпотентной миграции. Версии не повышаются на каждый коммит; только при релизе.

## 12. Показатели готовности MVP

- Один и тот же URL и одна сущность не попадают дважды при совпадающих маршрутах.
- Неопубликованные, закрытые ACL, `noindex`, технические и исключённые страницы не выдаются.
- Сборка продолжается после тайм-аута и не оставляет посетителей без прошлой успешной карты.
- Все части XML валидны и укладываются в лимиты протокола.
- Ошибка необязательного интеграционного плагина не ломает основной компонент.
- Чистая установка и обновление поверх предыдущего пакета сохраняют конфигурацию и состояние.
- Joomla видит обновление из публичного feed и успешно скачивает пакет с проверяемой контрольной суммой.
