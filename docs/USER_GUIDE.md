# Руководство администратора

## Установка

Установите `pkg_dharmasitemap-<версия>.zip` через **Система → Установка → Расширения**. Пакет ставит компонент, базовые источники Joomla, интеграцию Dharma Shop, системный endpoint, плагины Scheduler и CLI. После установки включите нужные плагины Dharma Sitemap в **Система → Плагины**. Интеграция магазина не требует `com_dharmashop` и просто пропускает источники при его отсутствии.

## Первая сборка

Откройте **Компоненты → Dharma Sitemap**, нажмите **Собрать сейчас** и дождитесь сообщения об успехе. После успешной сборки компонент показывает количество URL и дублей, а также адрес XML-файла. Если карта помещается в один файл, `/sitemap.xml` сразу содержит список URL; если URL больше лимита одной части, корневой файл становится sitemap index. До первой успешной сборки endpoint отвечает 503.

Во время новой сборки посетители продолжают получать прошлую успешную версию. Ошибка не активирует частичный набор.

## Что попадает в карту

В карту попадают только опубликованные записи, открытые гостю (уровни доступа гостя, а не «уровень 1» по умолчанию), в опубликованных и открытых ветках категорий, без `noindex`.

| Страницы | Источник | Условие |
| --- | --- | --- |
| Материалы, контакты, ленты, метки Joomla | Joomla | опубликованы, даты публикации, доступ гостю |
| Категории Joomla | Joomla | есть опубликованные записи, включая вложенные категории (настройка «Пропускать пустые категории») |
| Товары Dharma Shop | Dharma Shop | опубликованы; при настройке магазина «главный вариант» — только главный вариант группы |
| Категории, бренды, бейджи («метки») | Dharma Shop | опубликованы, есть опубликованные товары |
| Посадочные страницы | Dharma Shop | опубликованы, условия рабочие, открыта категория-источник |
| Главная, списки категорий, брендов, бейджей и посадочных, избранные материалы | Меню | пункт меню опубликован и открыт гостю |
| Корзина, оформление заказа, избранное, мои заказы, оплата, поиск, вход, регистрация | — | **не добавляются никогда**: личные страницы, закрытые от индексации |

### noindex

Страница с `robots: noindex` (или `none`) в карту не добавляется, пока включена настройка **Не добавлять страницы с noindex**. Значение берётся так же, как при показе страницы: настройки записи (вкладка «Публикация» → «Метаданные»), затем параметры пункта меню, затем общие настройки (Joomla → Система → Общие настройки → Метаданные; для Dharma Shop — настройка «Robots» магазина). Во вкладке «Обзор» отчёт показывает, сколько страниц исключено; если закрыто много страниц, а вы этого не ожидали, проверьте общее значение robots.

Если у страницы есть несколько адресов (например, адрес через другой пункт меню), в карте остаётся адрес, который строит штатный маршрутизатор: он же указан в canonical страницы.

### robots.txt

Укажите карту в `robots.txt` отдельной строкой: `Sitemap: https://example.com/sitemap.xml`. Компонент не меняет `robots.txt` сам.

## Источники и настройки

В настройках компонента можно включать материалы/категории, контакты, ленты новостей и метки Joomla; товары, категории, бренды, бейджи и посадочные страницы Dharma Shop; страницы из меню.

Необязательный канонический URL используется для выбора основного домена в `<loc>`. Указывайте корень сайта, например `https://example.com/`, без пути и query string. Параметры рекламных кампаний удаляются при нормализации. Значимые для маршрута параметры Joomla сохраняются.

После сборки компонент публикует статический `https://example.com/sitemap.xml` в корне сайта. При размере больше лимита он становится sitemap index и ссылается на версионные статические части `sitemap-<build>-<part>.xml`. Исходные файлы сборки также сохраняются в Joomla Cache, а старый Joomla endpoint оставлен как резерв. Существующий `sitemap.xml`, который не содержит маркер Dharma Sitemap, никогда не перезаписывается: сборка останавливается с пояснением.

## Настройки

Настройки находятся во вкладке **Настройки** на главной странице компонента.

- **Общие настройки:** канонический корневой адрес, список рекламных query-параметров для удаления (`*` в начале или конце имени — любое продолжение, например `mc_*`), лимит URL на XML-файл, **Не добавлять страницы с noindex** и **Хранить сборок** (сколько последних успешных сборок оставлять, по умолчанию 3; остальные удаляются вместе со строками БД и файлами частей).
- **Источники URL:** переключатели для материалов/категорий Joomla, контактов, лент, меток, страниц из меню, товаров, категорий, брендов, бейджей и посадочных Dharma Shop, а также **Пропускать пустые категории**. Дополнительные плагины могут добавлять источники и собственные параметры.
- **Исключения:** пути с шаблонами `*` и `?` либо записи `provider:id`, по одному правилу на строку. Например: `dharmashop.products:456`. Публичный доступ и публикация всё равно проверяются отдельно.
- **Автоматизация:** ссылка на штатный Joomla Scheduler и команда CLI. Команда запускается из корня сайта после включения плагина Dharma Sitemap — CLI.
- **Права доступа:** штатная ACL-матрица Joomla, доступная администраторам компонента.

Для расписания создайте задачу Dharma Sitemap в **Компоненты → Планировщик задач** и задайте интервал. Задача использует сохранённые источники и фильтры.

## Автоматическая сборка

В **Компоненты → Планировщик задач** создайте задачу **Пересобрать карту сайта Dharma Sitemap** и задайте интервал/время выполнения. Плагин использует те же настройки и логику, что ручной запуск.

## Запуск через Joomla CLI

Включите плагин **Dharma Sitemap — CLI** в списке плагинов. Из корневого каталога Joomla выполните:

```sh
php cli/joomla.php dharmasitemap:build
```

Команда использует те же источники, фильтры и блокировку, что и административный запуск и Scheduler. Код завершения `0` означает успешную публикацию; `1` означает ошибку.

## Плагины источников

Поставщики URL подключаются через группу `dharmasitemap` и событие `onDharmaSitemapCollectSources`. Контракт описан в [руководстве разработчика](DEVELOPER_GUIDE.md). Не добавляйте в источник закрытые страницы, неглавные варианты товаров, корзину, поиск и страницы личного кабинета; передавайте `robots` страницы, чтобы координатор исключил `noindex`.
